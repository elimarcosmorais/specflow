# T2 — Pagar v1/DT-02: atributo path no log config.invalid

- **Fase:** 1 — Pagamento de débitos
- **Depende de:** —
- **Débitos:** v1/DT-02 (média, origem: revisão da T6 da v1) — [debts.md](../../v1/debts.md)
- **Spec vigente:** [spec.md](../../v1/spec.md) §4.3, §8 (tabela de eventos de log), §10.2 (CT-30)

---

## 1. Objetivo

O log `config.invalid` passa a trazer o atributo `path` exigido pela spec §8. Assim o operador vê
qual `config.json` foi regravado, e o núcleo de Preferências continua sem importar
infraestrutura.

## 2. O que fazer

- Em `preferences.NewService`, acrescentar o parâmetro `configPath string` logo depois de
  `repo`, guardado num campo do `Service`. É o mesmo padrão das outras features, que recebem
  caminhos como `string` (`projects.NewService(repo, installRoot, …)`,
  `system.NewService(…, logsDir, …)`). Atualizar o comentário do `NewService`.
- Nos dois ramos de `config.invalid` do `Load` (conteúdo ilegível e campo inválido), logar
  `"path", s.configPath` antes de `"err"`.
- Atualizar todos os chamadores para passar o caminho do arquivo:
  - `cmd/dev-tools/main.go`: `paths.ConfigFile` (o mesmo passado ao `NewFileRepository`);
  - `preferences_integration_test.go` e as duas chamadas em `projects_integration_test.go`: o
    `paths.ConfigFile` do ambiente de teste;
  - `service_test.go` (`newTestService`): um caminho fixo, como `config.json`.
- CT-30 (`TestService_Load_InvalidFile`): além de `level=WARN msg=config.invalid`, verificar que
  a linha traz `path=` com o caminho passado ao serviço. Não é um CT novo: é o CT-30 conferindo
  o atributo que a spec §8 já define.

**Não fazer:**

- Corrigir outros problemas do mesmo arquivo que não estão nesta task. Achou outro? Cite-o nas
  "Pendências" da sua resposta: a revisão o registra como novo débito no `debts.md` desta versão.
- Alterar comportamento: resposta de API, erro, mensagem, dado gravado. Se a correção exigir
  isso, pare e avise: não é débito, é mudança.
- Mudar a interface `Repository`, o `FileRepository` ou os outros eventos de log
  (`config.created`, `preferences.updated`).
