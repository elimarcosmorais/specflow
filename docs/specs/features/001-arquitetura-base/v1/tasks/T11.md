## 1. Objetivo

O front faz o bootstrap e passa a falar com a API pelo cliente tipado. Ele tem:

- o shell com o menu lateral;
- tema e idioma aplicados;
- a tela de Status (saúde, avisos de porta ocupada e de API fora do ar, abrir a pasta de logs);
- a tela de Preferências, que muda tema e idioma na hora.

É a primeira task que liga o front à API, e por isso valida as duas hipóteses de §13 sobre o
front.

## 2. O que fazer

- **Tipos:** rode `npm run gen:api` para gerar `src/shared/api/schema.d.ts`. **Se o
  `openapi-typescript` falhar com o `openapi.yaml` 3.1, pare e pergunte** (§13: escrever os
  tipos à mão diverge da ADR 008).
- `app/bootstrap.ts`: chama `Bootstrap()` de `wailsjs/go/desktop/Bridge` e tipa o
  `BootstrapInfo` (§3.3.1).
- `shared/api/client.ts`:
  - `configureApi(baseUrl, token)`.
  - `apiFetch` sobre `fetch`, com `Authorization: Bearer <token>` e JSON.
  - Status ≥ 400 → `ApiError {status, code, message, field}`, lido do corpo de erro de §3.1.
  - Falha de rede vira um erro que a tela consegue distinguir, para mostrar `errors.network`
    (§6.2).
- `shared/i18n/`:
  - `pt-br.ts` é um objeto `as const`, e dele sai o tipo `Messages`; `en.ts` é tipado como
    `Messages`.
  - `I18nProvider.tsx` traz o contexto, `useT()` e `setLanguage`.
  - Os catálogos têm os textos do shell, de Status e de Preferências, os estados de §7.2 dessas
    telas, os nomes dos temas e `errors.network`. Os textos de Projetos são da T12.
- `shared/theme/`:
  - `applyTheme(theme)` grava `data-theme` no `<html>`.
  - `theme.css` define as variáveis de cor para `[data-theme=light]` e `[data-theme=dark]`, e o
    `system` usa `@media (prefers-color-scheme: dark)`.
  - Fonte `system-ui` (RN-06).
- `app/App.tsx`, substituindo o provisório:
  1. Ao montar, faz o bootstrap, chama `configureApi`, aplica idioma e tema.
  2. Guarda o estado da tela (`"projects" | "preferences" | "status"`) e mostra o menu lateral
     fixo com os três itens.
  3. Se `apiStatus ≠ "ok"`: desabilita Projetos e Preferências com a dica de §7.2 e abre na tela
     de Status. Senão, abre em Projetos.
  4. A área de Projetos fica com um espaço reservado até a T12.
- `app/app.css`: o layout do shell. `main.tsx` passa a importar os estilos globais.
- `features/system/`:
  - `api.ts`: `getHealth`, `openLogsFolder`.
  - `StatusPage.tsx` mostra versão, banco, endereço da API e da documentação (texto
    selecionável) e a pasta de logs, com os estados de §7.2: API no ar (carrega a saúde ao
    abrir), banco indisponível, porta ocupada (versão e banco vêm do bootstrap; botão
    desabilitado), `failed` e erro ao abrir a pasta.
- `features/preferences/`:
  - `api.ts`: `savePreferences`.
  - `PreferencesPage.tsx`: tema em opções de rádio, idioma em lista.
  - Trocar uma opção faz o `PUT` na hora, com as opções desabilitadas enquanto salva.
  - Ao receber `200`: `applyTheme` e `setLanguage`.
  - Em erro: mostra a `message` e volta à opção anterior.
- **CORS e Private Network Access (§13):** confira, no `wails dev` e no exe do `wails build`,
  que o WebView2 chama a API com `Authorization`. Se for barrado, pare e avise.
- Sem bibliotecas de estado, de componentes nem de rotas (ADR 008).

## 5. ADRs que se aplicam

- [ADR 008](../../../../../adr/008-organizacao-do-front.md) — React puro com CSS próprio; pastas por feature espelhando o motor; tema por variáveis CSS ("Sistema" segue `prefers-color-scheme`); chamadas com `fetch`; tipos gerados do `openapi.yaml`; sem bibliotecas de estado nem de componentes.
- [ADR 004](../../../../../adr/004-acesso-a-api-local-token-por-execucao-e-bootstrap-do-front.md) — o front chama `Bootstrap()` uma vez; depois dela, toda comunicação segue pela API HTTP.
- [ADR 005](../../../../../adr/005-padrao-de-erros-e-idiomas.md) — o front traduz o que desenha (catálogo das telas); as mensagens de erro da API já chegam traduzidas.
