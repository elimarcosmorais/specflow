# T1 — Esqueleto Wails (motor + front)

- **Fase:** 1 — Esqueleto
- **Depende de:** —
- **Entrega para outras tasks:** módulo Go `dev-tools` (`go.mod`); pacote `frontend` com
  `Assets()`; projeto Wails (`cmd/dev-tools/wails.json`); `cmd/dev-tools/main.go` provisório;
  projeto Vite/React com os scripts `dev`, `build`, `gen:api` e `typecheck`; `src/app/App.tsx`
  provisório
- **Histórias:** US-03 · **Critérios de aceite:** — (o CT-83 valida a hipótese de §13)
- **Spec:** [spec.md](../spec.md) §1, §8 (Desenvolvimento), §11, §13 (primeira linha)

## 1. Objetivo

O app abre uma janela Wails ("Dev Tools") a partir de `dev-tools/cmd/dev-tools/`, com o front
React embutido. Isso prova, antes de qualquer outra task, que o `wails.json` em `cmd/dev-tools/`
funciona com o Wails v2 (primeira hipótese de §13), condição para cumprir o caminho da ADR 002.

## 2. O que fazer

- Criar a pasta `dev-tools/` na raiz do repositório (D-11).
- `go.mod`: `module dev-tools`, `go 1.25`, com `github.com/wailsapp/wails/v2`. As outras
  dependências de §11 entram nas tasks que as usam.
- `.gitignore` com `build/bin/`, `frontend/node_modules/`, `frontend/dist/app/` e `.dev-home/`.
- `cmd/dev-tools/wails.json` com os valores de §8 (Desenvolvimento).
- `cmd/dev-tools/main.go` **provisório**: `var version = "0.1.0"` e `wails.Run` com título
  `Dev Tools`, 1100×720 (mínimo 900×600) e `AssetServer.Assets = frontend.Assets()`. A sequência
  completa de §6.1 é da T10.
- `build/`: `appicon.png`, `windows/icon.ico`, `windows/info.json` (nome `Dev Tools`, versão
  `0.1.0`) e `windows/wails.exe.manifest` com `requestedExecutionLevel level="asInvoker"`
  (RN-01). Parta dos arquivos que o próprio Wails gera.
- Front:
  - `package.json` já completo, como em §11: `react` 19, `react-dom`, `vite`, `typescript`,
    `@vitejs/plugin-react` e `openapi-typescript` (dev). Scripts: `dev`, `build`,
    `typecheck` (`tsc --noEmit`) e `gen:api`, que gera `src/shared/api/schema.d.ts` a partir de
    `../internal/platform/httpserver/docs/openapi.yaml`. O arquivo YAML só nasce na T5; aqui o
    script só fica declarado.
  - `package-lock.json` (via `npm install`), `tsconfig.json` com `strict`, `vite.config.ts`
    com `build.outDir = dist/app`, `index.html` e `src/main.tsx`, que monta o `App`.
  - `src/app/App.tsx` **provisório**: só o título "Dev Tools". O shell é da T11.
  - Sem bibliotecas de estado, de componentes nem de rotas (ADR 008).
- `frontend/embed.go`: `package frontend`, `//go:embed all:dist` e `Assets()` =
  `fs.Sub(..., "dist/app")`. `frontend/dist/.gitkeep` mantém a pasta, para `go test ./...`
  compilar antes do primeiro build do front (§8).
- `frontend/wailsjs/`: gerado pelo Wails (runtime). O binding `Bootstrap` só nasce na T10.
- **Se o `wails build` ou o `wails dev` falhar por causa do `wails.json` em `cmd/dev-tools/`:
  pare e avise.** Pela §13, o caminho é registrar uma ADR que substitua a 002 nesse ponto. Não
  mova o `main.go` por conta própria.
