## 1. Objetivo

`wails build -nsis` gera um instalador que roda como usuário comum, sugere `C:\dev-tools`, não
escreve no registro e tem um desinstalador que pergunta sobre os dados e nunca toca em
`projects\`. O `README.md` explica como rodar, testar, gerar os tipos, compilar e gerar o
instalador.

## 2. O que fazer

- **Pré-requisito:** NSIS 3.x (`makensis`) em `C:\dev\programs\nsis\nsis-v3.x.x`, com o atalho
  `current` no `PATH` (§3.3.4). Hoje ele não está instalado. **Se `makensis -VERSION` falhar,
  pare e peça ao usuário para instalar.**
- Rode `wails build -nsis` em `dev-tools/cmd/dev-tools` uma vez, para o Wails gerar
  `build/windows/installer/project.nsi` e `wails_tools.nsh`.
- Ajuste os dois arquivos linha a linha conforme a tabela de §3.3.4:
  - `RequestExecutionLevel user`;
  - `InstallDir "C:\dev-tools"` com `MUI_PAGE_DIRECTORY`;
  - o exe em `$INSTDIR\programs\`; as pastas `programs\{data,logs}` e
    `projects\{web,android,windows}`;
  - os atalhos com `SetShellVarContext current`;
  - o desinstalador em `$INSTDIR\programs\uninstall.exe`, **sem** as escritas de registro de
    `wails.writeUninstaller` e sem associações de arquivo;
  - a macro `wails.webview2runtime` mantida;
  - os idiomas English e PortugueseBR, com `MSG_REMOVE_DATA`;
  - a seção de desinstalação com **Sim/Não**. Nenhum comando toca em `$INSTDIR\projects`, e
    `RMDir "$INSTDIR"` vai sem `/r`.
- `README.md` (§8, Desenvolvimento):
  - Pré-requisitos: Go, Wails, Node e NSIS.
  - Rodar em desenvolvimento: `wails dev` com `DEV_TOOLS_HOME` e `DEV_TOOLS_API_PORT=41791`.
  - Testes: `go test ./...` e `go test -tags integration ./...`.
  - Tipos do front: `npm run gen:api` e `npm run typecheck`.
  - Build: `wails build`.
  - Instalador: `wails build -nsis`, com a saída
    `dev-tools/build/bin/dev-tools-amd64-installer.exe`.
- Os manuais desta task usam o instalador gerado, numa conta Windows **padrão** (sem admin).
