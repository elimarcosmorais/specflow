# T4 — Banco de dados e migrações

- **Fase:** 2 — Infraestrutura comum
- **Depende de:** T1 (usa `go.mod`)
- **Entrega para outras tasks:** `db.Open`, `db.Migrate`, `db.ErrSchemaNewer`, `db.Pinger` e a
  tabela `projects`
- **Histórias:** US-06, US-16 · **Critérios de aceite:** CA-12, CA-40, CA-41
- **Spec:** [spec.md](../spec.md) §3.3.2 (`db`), §4.1, §4.2, §5 (última linha, D-06), §8 (Logs:
  `db.opened`, `db.migration_applied`)

---

## 1. Objetivo

O pacote `internal/platform/db` abre o SQLite, aplica as migrações embutidas com
`PRAGMA user_version` e oferece o `Pinger` usado pela saúde. A tabela `projects` nasce na
migração `0001`.

## 2. O que fazer

- `migrations/0001_create_projects.sql`: tabela `projects` com as colunas, os tipos e as
  restrições de §4.1, incluindo os `UNIQUE` de `name_key` e `path_key` e o `CHECK` de `type`.
- `db.go`:
  - `//go:embed migrations/*.sql`.
  - `Open(ctx, path, logger)`:
    1. `sql.Open("sqlite", …)` com a string de conexão de §4.1 e `SetMaxOpenConns(1)`.
    2. `Ping`.
    3. `Migrate` com as migrações embutidas.
    4. Loga `db.opened path=… schema_version=…`.
    5. Em erro, fecha a conexão e devolve o erro. O modo degradado é decidido pelo `main.go`
       (T10).
  - `Migrate(ctx, db, migrations, logger)`, conforme §4.2:
    1. Os nomes seguem `NNNN_<descricao>.sql`. Numeração com buraco ou repetida → erro.
    2. Lê `PRAGMA user_version`. Se for maior que a última migração conhecida →
       `ErrSchemaNewer`.
    3. Aplica, em ordem, cada migração de versão maior, numa transação por arquivo que termina
       com `PRAGMA user_version = NNNN`.
    4. Loga `db.migration_applied version=… file=…` para cada uma.
  - `Pinger{DB}.Ping(ctx)`: `DB` nulo → erro; senão, o `PingContext` do banco.
- `go.mod`/`go.sum`: `modernc.org/sqlite` (driver `"sqlite"`, sem CGO).
