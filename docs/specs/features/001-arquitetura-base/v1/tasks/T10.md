## 1. Objetivo

O pacote `internal/platform/desktop` está pronto e o `main.go` monta o app inteiro na sequência
de §6.1:

- instância única;
- diálogo fatal traduzido;
- modo degradado com o banco fora do ar;
- porta ocupada;
- bootstrap para o front;
- encerramento limpo.

As rotas de todas as features batem com o `openapi.yaml`.

## 2. O que fazer

- `desktop/bridge.go`:
  - `BootstrapInfo` com os campos e as tags JSON de §3.3.1.
  - `NewBridge(static, prefs func() (theme, language string))`.
  - `Bootstrap()` devolve os campos estáticos mais as preferências atuais, lidas a cada chamada.
  - `Bootstrap()` é o **único** método exportado do `Bridge` (CT-25).
- `desktop/window.go`:
  - `Window` guarda o `ctx` do Wails.
  - `Startup(ctx)`.
  - `Focus()` = `WindowUnminimise` + `Show`.
  - `ApplyTheme(theme)` chama `runtime.WindowSetLightTheme`, `WindowSetDarkTheme` ou
    `WindowSetSystemDefaultTheme`; antes do `Startup`, não faz nada.
  - `WindowsTheme(theme)`: `"light"` → `Light`, `"dark"` → `Dark`, qualquer outro →
    `SystemDefault`.
- `desktop/messages.go`: `WebView2Messages(language)` preenche os 11 campos de
  `windows.Messages` com as chaves `webview2.*` do catálogo (T3).
- `desktop/instance.go`: `UniqueID(baseDir)` = `"dev-tools-"` + os 12 primeiros hex de
  `sha256(minúsculas(filepath.Clean(baseDir)))`.
- `desktop/dialog_windows.go`: `ShowFatal(title, message)` chama `MessageBoxW` com
  `MB_OK|MB_ICONERROR` (`golang.org/x/sys/windows`).
- `cmd/dev-tools/routes.go`:
  - `apiRoutes(...)` junta `projects.Routes`, `preferences.Routes` e `system.Routes`.
  - Precisa funcionar com dependências nulas, porque o CT-23 só lê método, caminho e `Public`.
- `cmd/dev-tools/main.go`: substituir o provisório da T1 pela sequência de §6.1, passos 1 a 9,
  e pelo encerramento:
  - **Passo 2 (falha no `EnsureLayout`):**
    1. Pega o idioma de `preferences.NewFileRepository(paths.ConfigFile).Load`, ou de
       `i18n.DetectWindows` se não der para ler.
    2. Chama `desktop.ShowFatal` com `startup.title` e `startup.folder_not_writable {path}`.
    3. Encerra com `os.Exit(1)`, sem logar nada.
  - **Passo 4:** loga `app.started`, um `layout.created` por pasta criada e um
    `config.invalid_env` por aviso de `LoadSettings`.
  - **Passo 5:** `onChange` chama `window.ApplyTheme`; `detectLanguage = i18n.DetectWindows`.
  - **Passo 6:** em falha, loga `db.open_failed` (ERROR), segue com `*sql.DB` nulo e
    `databaseStatus = "unavailable"`.
  - **Passo 7:** `cfg.Language` lê `prefs.Get().Language`; o `system.Service` recebe
    `db.Pinger{DB: conn}`.
  - **Passo 8:**
    - Sucesso → `go srv.Serve(ln)`, log `api.listening` e `apiStatus = "ok"`.
    - `ErrPortInUse` → log `api.port_in_use` e `apiStatus = "port_in_use"`.
    - Outro erro → log `api.listen_failed` e `apiStatus = "failed"`.
  - **Passo 9:**
    - O `Bridge` recebe `version`, `apiBaseUrl` (`http://127.0.0.1:<porta efetiva>`), `token`,
      `apiStatus`, `apiPort`, `databaseStatus` e `logsDir`.
    - As opções do `wails.Run` são exatamente as do passo 9.
  - **Encerramento:** `srv.Shutdown` com prazo de 3 s → `conn.Close()` → `app.stopped` →
    fecha o logger.
  - O token nunca vai para log nem para disco.
- `frontend/wailsjs/`: regenerar (`wails generate module`, ou via `wails dev`/`build`) para
  existir `go/desktop/Bridge` só com `Bootstrap`.
- `go.mod`/`go.sum`: `gopkg.in/yaml.v3`, usado só no teste.
- **Manuais desta task:** usam o exe do `wails build`, porque o instalador é da T13. A tela do
  front ainda é provisória, e isso basta para eles. Onde o roteiro diz "atalho", use o exe. Para
  não criar pastas dentro de `build/`, rode o exe copiado numa pasta `...\programs\` própria.

## 5. ADRs que se aplicam

- [ADR 004](../../../../../adr/004-acesso-a-api-local-token-por-execucao-e-bootstrap-do-front.md) — token gerado a cada execução, só em memória; uma única chamada do Wails de bootstrap (endereço, token, estado e preferências); depois dela, tudo pela API HTTP.
- [ADR 003](../../../../../adr/003-aplicacao-portatil.md) — instância única com `SingleInstanceLock` (abrir de novo foca a janela); dados do WebView2 dentro da pasta do app; pasta sem escrita fecha com mensagem clara.
- [ADR 005](../../../../../adr/005-padrao-de-erros-e-idiomas.md) — o diálogo nativo e as mensagens do WebView2 saem no idioma salvo, pelo catálogo do motor.
- [ADR 002](../../../../../adr/002-arquitetura-em-camadas-e-padrao-de-feature.md) — `cmd/dev-tools/main.go` monta tudo; as features não se importam entre si (o `main.go` as liga com funções).
- [ADR 001](../../../../../adr/001-stack-base-do-dev-tools.md) — o teste de contrato (CT-23) garante que as rotas e o `openapi.yaml` não divergem.
