# T5 — Erros de domínio, servidor HTTP e documentação da API

- **Fase:** 3 — Erros e servidor HTTP
- **Depende de:** T3 (usa `i18n.T` e o catálogo com os códigos de §3.2)
- **Entrega para outras tasks:** `apperr` (`Kind`, `Error`, `New`, `WithField`, `Wrap`,
  `ErrInvalidBody`, `ErrTokenInvalid`, `ErrDatabaseUnavailable`, `ErrInternal`); `httpserver`
  (`HandlerFunc`, `Route`, `Config`, `NewHandler`, `NewToken`, `Listen`, `ErrPortInUse`,
  `WriteJSON`, `DecodeJSON`); `docs/openapi.yaml`
- **Histórias:** US-03, US-06, US-08, US-09, US-13, US-14 · **Critérios de aceite:** CA-07,
  CA-08, CA-13, CA-18, CA-23, CA-32, CA-33, CA-34, CA-35
- **Spec:** [spec.md](../spec.md) §2.2, §3.1, §3.2, §3.3.2 (`apperr`, `httpserver`), §5 (RN-06,

## 1. Objetivo

Existe o tipo de erro de domínio e o servidor HTTP comum, que tem:

- registro de rotas com token por padrão;
- CORS;
- recuperação de pânico;
- log de acesso;
- resposta de erro traduzida;
- `Listen` só em loopback;
- página `/docs` offline, com o contrato `openapi.yaml` de toda a API.

As features (T6 a T9) só precisam declarar as próprias rotas.

## 2. O que fazer

- `apperr/apperr.go`, conforme §3.3.2:
  - `Kind`, com as 7 constantes.
  - `Error{Kind, Code, Field, Err}`.
  - `New`.
  - `WithField` e `Wrap`, que devolvem cópia e não alteram o original.
  - `Error()`, `Unwrap()` e `Is`, que compara `Code`.
  - Os quatro erros comuns, com os códigos de §3.2: `request.invalid_body`,
    `auth.token_invalid`, `database.unavailable` e `internal.unexpected`.
  - Só importa a biblioteca padrão (§2.2).
- `httpserver/respond.go`:
  - `WriteJSON` com `Content-Type: application/json; charset=utf-8`.
  - `DecodeJSON`: `MaxBytesReader` de 1 MiB + `DisallowUnknownFields`; qualquer falha devolve
    `apperr.ErrInvalidBody` com a causa.
  - Escrita do erro:
    - `Kind` → status pela tabela de §3.2.
    - Corpo `{"error":{"code","message","field"}}`, com `field` omitido quando vazio.
    - `message = i18n.T(cfg.Language(), code, nil)`.
    - Erro que não é `apperr` → `500 internal.unexpected`.
    - A causa nunca vai ao cliente.
- `httpserver/middleware.go`, nesta ordem: recuperação → log de acesso → CORS → token por rota.
  - **Recuperação:** pânico → `500 internal.unexpected`.
  - **Log de acesso:**
    - `http.request` (DEBUG) com `method`, `path`, `status` e `duration_ms`.
    - `http.error`: WARN em 4xx, ERROR em 5xx, com `method`, `path`, `status`, `code` e `err`
      (o `err` só em 5xx).
    - Nunca loga o token, o cabeçalho `Authorization` nem corpos.
  - **CORS:**
    - Os cabeçalhos de §3.1 vão em toda resposta.
    - `OPTIONS` responde `204` sem exigir token e sem chamar o handler.
    - O preflight precisa ser atendido antes do `ServeMux`. Se não for, o `OPTIONS` numa rota
      só de `GET`/`POST` vira `405`.
  - **Token:**
    - Exige `Authorization: Bearer <token>`, comparado com `subtle.ConstantTimeCompare`.
    - Rotas com `Public = true` dispensam o token.
    - Falha → `401 auth.token_invalid`, sem chamar o handler.
- `httpserver/server.go`:
  - `HandlerFunc`, `Route`, `Config`.
  - `NewHandler(cfg, routes)`: `ServeMux` com padrões `"MÉTODO /caminho"`, mais as rotas
    `/docs` e os middlewares.
  - `NewToken()`: 32 bytes de `crypto/rand` em hexadecimal (64 caracteres).
  - `Listen(port)`: `127.0.0.1:<port>`; `WSAEADDRINUSE` → `ErrPortInUse`, de modo que
    `errors.Is` funcione.
- `httpserver/docs.go`: embed de `docs/` e as rotas públicas `GET /docs` (o `index.html`),
  `GET /docs/openapi.yaml` e `GET /docs/redoc.standalone.js`, cada uma com o `Content-Type`
  certo.
- `httpserver/docs/openapi.yaml`, OpenAPI 3.1 escrito à mão:
  - As 7 operações `/api` de §3.1, com corpo, respostas e os códigos de erro de cada uma.
  - Os tipos `Project`, saúde e preferências.
  - O formato de erro.
  - O esquema `bearer`, com `GET /api/health` sem segurança.
  - É o contrato que o CT-23 (T10) compara com as rotas e que o front usa para gerar os tipos
    (T11).
- `httpserver/docs/index.html`: página do Redoc que carrega `redoc.standalone.js` e
  `openapi.yaml` só por caminhos locais.
- `httpserver/docs/redoc.standalone.js`: Redoc 2.x numa versão fixada, baixada uma vez e
  versionada. Registre a versão num comentário no `index.html`.

## 5. ADRs que se aplicam

- [ADR 001](../../../../../adr/001-stack-base-do-dev-tools.md) — API com `net/http` da biblioteca padrão; contrato OpenAPI escrito à mão (`openapi.yaml`), servido numa página `/docs`.
